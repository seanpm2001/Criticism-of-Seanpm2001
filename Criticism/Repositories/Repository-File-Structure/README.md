# Repository file structure

I am sometimes criticized for the file structure of my repositories. In my older repositories that haven't been updated, the file structure is very bare, but nowadays, I follow a large template. All of these files do something.

Files, such as `AUTHORS` `CREDITS` and `INSTALL` were created, as I saw how the icons were displayed on the file icons on Ubuntu from a downloaded Wikimedia repository. I keep variants of these 3 files, bearing the file extensions required to run them properly, although these don't have the right icons (`AUTHORS.md` `CREDITS.wiki` `INSTALL.rst`)

The `ROOTFILES.base` file is a file that lists the file tree of the repository at the base of the branch. This file is in the URLL language, and can be opened for now with a text editor.

There are other files, such as `404.jpeg` `404.md` and `404.htm` which are used for 404 pages for the repository, and formerly, for GitHub Pages.

All of the files in the structure do something, and despite the complexity, it makes the project feel more complete, and more functional.
